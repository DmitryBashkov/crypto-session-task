1. Трехсторонний протокол распределения ключей

Для примера возьмем симметричный протокол Нидхема-Шредера: участники `A` и `B` получают общий сеансовый ключ через доверенный сервер `S`. До начала обмена у A и S уже есть общий долговременный ключ `K_AS`, а у `B` и `S` — ключ `K_BS`. Сервер хранит оба ключа. Непосредственно между `A` и `B` предварительного общего ключа не требуется

Ниже `E_K` означает шифрование на ключе `K`. `N_A` и `N_B` случайные числа для проверки ответов. Обмен состоит из пяти сообщений:

1. `A -> S: A, B, N_A` Инициатор сообщает серверу с кем хочет установить связь и передает случайное число для проверки ответа
2. `S -> A: E_K_AS(N_A, B, K_AB, E_K_BS(K_AB, A))`  Сервер создает сеансовый ключ `K_AB` и отправляет его `A` вместе с именем `B` и полученным числом `N_A`. Вложенная часть предназначена для `B` и защищена ключом `K_BS`. `A` расшифровывает внешнюю часть и проверяет `N_A` и имя `B`.
3. `A -> B: E_K_BS(K_AB, A)` `A` пересылает предназначенную для `B` часть, `B` расшифровывает ее своим долговременным ключом и получает `K_AB` и имя `A`
4. `B -> A: E_K_AB(N_B)` `B` отправляет собственное случайное число зашифрованное сеансовым ключом чтобы проверить владение этим ключом.
5. `A -> B: E_K_AB(N_B − 1)` `А` расшифровывает запрос и уменьшает число на единицу и возвращает зашифрованный результат. `B` проверяет ответю

Результат:
общий симметричный сеансовый ключ `K_AB` у `A` и `B`. Его знает также сервер `S`, поскольку именно он его создал. Последние два сообщения предназначены для подтверждения владения сеансовым ключом.

Недостаток: 
если нарушителю стал известен старый сеансовый ключ, он может повторно отправить старое третье сообщение и ответить на проверку `B`. `B` при этом не проверяет свежесть самого сеансового ключа. Один из способов исправления это включение проверяемой временной метки и ограничение срока действия ключа.

2. Формальные модели шифров

Алгебраическая модель описывает множества допустимых данных и преобразования между ними. Ее можно записать как систему `(X, K, Y, E, D)`, где:
    Х - ножество открытых текстов
    K - множество ключей,
    Y - множество шифртекстов,
    E - семейство шифрующих отображений
    D - семейство расшифровывающих отображений. 
Для симметричного шифра основное условие корректности имеет вид:

`D_k(E_k(x)) = x`

Те расшифрование с правильным ключом должно возвращать исходное сообщение. Поэтому при фиксированном ключе два разных открытых текста не могут зашифровываться в один и тот же шифртекст, иначе однозначно выбрать исходный текст было бы невозможно. Плюс, множество `Y` составляют именно те шифроексты, которые могут получиться хотя бы при одной допустимой паре текста и ключа.

Назначение алгебраической модели заколючается ва описании структуры шифра и проверке корректности расшифрования. Но выполнение этих условий не доказывает стойкостьтк, например, сдвиг букв на заданное ключом число позиций обратим, но одной обратимости недостаточно для защиты информации.

Вероятностная модель добавляет к алгебраической модели распределения вероятностей открытых текстов и ключей. В базховой модели они независимы, таким образом ее компоненты `X, K, Y, E, D` и распределения `P(X)`, `P(K)`. Они позволяют вычислить вероятность шифротекстов и оценивить, как перехват сообщения меняет сведения нарушителя об открытом тексте или ключе.

В этой модели определяется секретность, то есть для каждого наблюдаемого шифртекста вероятность открытого текста после перехвата остается такой же, как до перехвата. Условие можно записать так:

`P(X = x | Y = y) = P(X = x)`

Алгебраическая модель отвечает на вопрос как устроено преобразование, а вероятностная позволяет анализироватьк акую информацию раскрывает его результат.

3. Принципы построения поточных систем

Поточный шифр обрабатывает последовательность данных по мере поступления. В распространенной двоичной схеме генератор вырабатывает гамму, которая складывается с открытым текстом побитовым xor. Для расшифрования повторно применяется xor с той же гаммой.

`c_i = m_i XOR z_i`
`m_i = c_i XOR z_i`

гнде `m_i` — это лемент открытого текста, `c_i` — шифртекста, `z_i` — гаммы

Короткий секретный ключ используется для выработки длинной псевдослучайной гаммы. Требуется, чтобы злоумышленник не мог эффективно предсказывать ее неизвестную часть по извесьтным данным. Просто случайного внешнего вида недостаточно,тк генератор может иметь хорошие статистические показатели и при этом быть предсказуемым.

Для гаммы нужны большой период, высокая линейная сложность и хорошие статистические свойства. Большой период ограничивает повторения, высокая линейная сложность затрудняет восстановление линейной рекуррентной связи, при этом статистические свойства препятствуют обнаружению простых закономерностей. Эти требования необходимы для классических генераторов на регистрах сдвига, но их выполнение еще не доказывает криптографическую стойкость.

Линейный регистр сдвига с обратной связью LFSR удобен для реализации, однако его нельзя использовать как самостоятельный генератор гаммы, тк при линейной сложности `L` алгоритм Берлекэмпа-Мэсси восстанавливает порождающий регистр по `2L` последовательным битам выхода. Поэтому для этого применяют нелинейное объединение выходов нескольких регистров, нелинейную фильтрацию состояния одного регистра или управление тактированием одних регистров с помощью других. Для комбинирующих функций также проверяют устойчивость к корреляционным атакам и одной нелинейности недостаточно.

В синхронной системе гамма не зависит от открытого текста и шифртекста, поэтому обе стороны должны использовать одинаковые начальные параметры и одинаковую позицию в гамме, тк вставка или удаление данных нарушает синхронизацию. В самосинхронизирующейся системе гамма зависит от ключа и ограниченного числа предыдущих символов шифртекста. После приема достаточного числа правильных символов корректное расшифрование восстанавливается автоматически.

Для систем с nonce или IV требуется соблюдать правила их использования. Например в ChaCha20 нельзя повторять nonce при том же ключе. Повтор одинаковой гаммы раскрывает xor двух открытых текстов, поскольку одинаковые биты гаммы взаимно уничтожаются при сложении шифртекстов.

Генератор должен быть эффективным на целевой платформе. Простые операции и небольшой объем памяти позволяют обрабатывать поток без большой задержки. При этом шифрование через xor само по себе не защищает целостность, тк зменение бита шифртекста предсказуемо меняет соответствующий бит сообщения,ап значит для обнаружения подделки требуется аутентификация.

4. Режим без требования биективности

Режим счетчика CTR это прямое преобразование и применяется к блоку счетчика, а его результат используется как гамма. К примеру6 оозначим через `T_i` блок счетчика, а через `F_K` детерминированное ключевое преобразование и через `P_i` и `C_i` блоки открытого текста и шифртекста. Схема:

`G_i = F_K(T_i)`
`C_i = P_i xor G_i`
`P_i = C_i xor G_i`

Получатель по ключу и значению счетчика вычисляет ту же гамму, поэтому восстанавливать `T_i` по `G_i` ему не нужно. Поэтому обратное отображение для `F_K` не используется, а однозначность расшифрования следует из обратимости xor по открытому тексту:

`(P_i xor G_i) xor G_i = P_i`

Таким образом биективность F_K не нужна именно для корректности этой конструкции,, тк если разные значения счетчика дадут одинаковую гамму, то каждый блок все равно можно однозначно расшифровать при известных ключе и счетчике.

PS В данном случае корректность не следует смешивать со стойкостью как говорилось выше, тк произвольная необратимая функция может вырабатывать предсказуемую гамму. В обычном CTR дополнительно требуется, чтобы значения счетчиков не повторялись ни внутри сообщения ни между сообщениями на одном ключе.

5. Распространение ошибки в CFB

По условию рассматриватем CFB-8, то есть базовый блочный шифр имеет блок 64 бита, а открытый текст и шифртекст обрабатываются сегментами по 8 бит. Регистр обратной связи содержит 64 бита, значит на каждом шаге он шифруется, а из результата берутся 8 старших бит гаммы, которые складываются по xor с очередным сегментом. Затем регистр сдвигается на 8 бит влево, а справа в него записывается сегмент шифртекста и при расшифровании используется именно принятый сегмент шифртекста.

Пусть один бит исказился в сегменте `C_j`. Распространение ошибки происходит в следующем порядке.

1. При восстановлении `P_j` гамма еще правильная, она получена из предыдущего состояния регистра. Поэтому в `P_j` изменится ровно тот бит, который изменился в `C_j`.
2. Искаженный `C_j` записывается в регистр обратной связи. Регистр вмещает `64 / 8 = 8` сегментов, поэтому ошибочный бит остается в нем в течение восьми следующих циклов.
3. Из-за неверного состояния регистра гамма для `P_(j+1)..P_(j+8)` может отличаться от правильной. В этих сегментах возникают непредсказуемые ошибки и для идеализированного стойкого шифра вероятность ошибки отдельного бита составляет `0,5`.
4. Перед обработкой `P_(j+9)` ошибочный сегмент уже вытеснен из регистра, поэтому дальнейшее расшифрование снова правильно, если новых ошибок нет.

Область распространения ошибки охватывает исходный сегмент и восемь следующих, таким образом  всего 9 байтов, или 72 битовые позиции. При этом не факт что изменятся все 72 бита, так как в первом байте меняется один бит, а в последующих байтах ошибки носят случайный характер.

Для наглядности предположим, что ошибка находится в третьем байте `C_3`: тогда `P_3` содержит одну битовую ошибку, `P_4..P_11` попадают в область случайных ошибок, а с `P_12` расшифрование снова правильно. Первый 64-битовый блок содержит `P_1..P_8`, второй — `P_9..P_16`, поэтому область ошибки пересекает только два блока.

Ответ:
Исказится два 64-битовых блока открытого текста, тк девять последовательных байтов пересекают границу блока из восьми байтов, но не выходят за пределы двух иэтих блоков.

6. Длина хэша и вероятность коллизии

Расчет выполняется в модели, где хэши двух различных случайных сообщений независимы и равномерно распределены по всем n-битовым значениям. Число возможных значений равно:

`N = 2^n`

Сначала фиксируется хэш первого сообщения; у второго сообщения при равномерном распределении есть N равновероятных результатов, и только один совпадает с первым. Это частный случай модели задачи о днях рождения для двух сообщений. Поэтому вероятность коллизии одной пары равна:

`p = 1 - (1 - 1/N) = 1/N = 2^(-n)`

Из условия задачи следует неравенство:

`2^(-n) <= 10^(-9)`

Обе части положительны, поэтому после перехода к обратным величинам знак неравенства меняется:

`2^n >= 10^9`

Логарифмирование по основанию 2 дает:

`n >= log2(10^9)`
`n >= 9 * log2(10)`

Подстановка численного значения логарифма:

`log2(10) = 3.32`
`n >= 9 * 3.32 = 29.9`

Длина вектора это целое число, поэтому минимальное значение` n = 30`. Проверяем соседние значения:

`2^(-30) = 9.31 * 10^(-10) < 10^(-9)`
`2^(-29) = 1.86 * 10^(-9) > 10^(-9)`

Ответ: 
`n >=30`, минимальная длина 30 бит
